# Audio Visual Analyzer 超進化構想書

- Date: `2026-09-28`
- Status: **構想（未実装・オーナー判断待ち）**
- 対象: `doc/spec.md` v2.5（Phase 14.2 完了時点）

## 0. 結論（1行）

**「スペクトルを描く道具」から「音楽を理解し、演出し、書き出す、インストール不要の映像エンジン」へ。**
鍵は、ライブ再生とオフライン書き出しで完全に同一の **音楽特徴ストリーム（Music Feature Stream / MFS）** を1本通し、全表現をその上に載せ替えること。

---

## 1. 守るもの（根本コンセプトの定義）

`doc/spec.md` §2・§24・§25 から、進化後も絶対に崩さない不変条件を抽出した。以降の全提案はこのフィルターを通過したものだけを載せている。

| # | 不変条件 | 根拠 |
|---|---|---|
| C1 | `index.html` を開くだけで動く。npm・ビルド・サーバー不要 | §2.1, §24-1, §25 |
| C2 | 外部ライブラリなし。Web 標準 API のみ | §2.1 |
| C3 | 音声/動画ファイル入力 → 音に反応する映像 | §1, §25 |
| C4 | 再生モード（鑑賞）と録画モード（書き出し）の二本柱 | §1, §25 |
| C5 | ビジュアライザーが主役、UI は簡素 | §2.2 |
| C6 | 背景は黒または白 | §25 |
| C7 | 16:9 / 1:1 対応 | §25 |

**解釈の要点**: C1/C2 は「ユーザーに何も要求しない」ことが本質。したがって **WebGL2 / Web MIDI / Service Worker / File System Access 等の“ブラウザ標準API”の採用は C2 違反ではない** と判断している（要オーナー確認 → §8 D1）。

## 2. 現状診断 — 何が強く、何が天井か

### 2.1 すでに持っている“異常に強い”資産
1. **決定的なオフライン書き出しパイプライン**（OfflineAudioContext + 自前FFT + WebCodecs + 自前 MP4/WebM マクサー/デマクサー）。これは Web ビジュアライザーとしては例外的な資産で、**「未来を知った状態で描ける」** という能力を既に内包している。
2. **レンダラー契約**（`doc/renderer-contract.md`）による14タイプの交換可能な表現。
3. **外部依存ゼロ**で上記を実現している事実そのもの。

### 2.2 天井（進化を阻むボトルネック）

| 領域 | 現状 | 天井 |
|---|---|---|
| 解析 | `AnalyserNode` の 8bit スペクトル、線形ビン等分でレイヤー分割（`audio-engine.js` `getLayerData`） | 人の聴感（対数周波数）とずれる。低域が1レイヤーに潰れ、高域が過大 |
| 解析 | モノラル（ステレオ情報を捨てている） | 左右の広がり・定位を表現に使えない |
| リズム | 低域EMA比の閾値ビート検出（`BeatDetector`） | テンポ・拍位相・小節頭を知らない。「拍に合わせて切り替える」ができない |
| 構造 | なし | イントロ/サビ/ドロップを知らないため、曲全体を通した“演出”ができない |
| 描画 | Canvas 2D のみ | 粒子数・ポストエフェクト（グロー、フィードバック、歪み）に性能上限 |
| 操作 | 静的パラメーター＋手動ランダム | 時間変化は色相連続変化のみ。パラメーターが音に“連動”しない |
| 同一性 | ライブ（AnalyserNode）とオフライン（自前FFT）で経路が別 | 「プレビューで見たもの＝書き出されるもの」の保証が間接的 |
| 品質保証 | E2E/単体テストスクリプトがリポジトリ外（`log.md` に記録のみ） | 回帰の再現性がオーナー環境に依存 |

## 3. 進化の中心アイデア: 4つの力

```
      ┌──────────────── 聴く（Perception）────────────────┐
音源 →│ MFS: 聴感帯域 / オンセット / テンポ・拍位相 / 構造 / │→ 特徴ストリーム
      │      ステレオ / 音色 / ラウドネス                  │   （ライブ・オフライン同一）
      └───────────────────────────────────────────────────┘
                              ↓
      ┌── 繋ぐ（Modulation）── 任意の特徴 → 任意のパラメーター ──┐
                              ↓
      ┌── 描く（Expression）── WebGL2 レンダラー + ポストFX ─────┐
                              ↓
      ┌── 演じる（Direction）── 自動演出 / ライブ操作 / タイムライン ┐
                              ↓
                 再生モード（鑑賞・演奏） / 録画モード（書き出し）
```

---

## 4. 各力の詳細設計

### 4.1 聴く — Music Feature Stream（MFS）

すべての表現の入力を `frame.freq`（8bit配列）から **意味のある特徴ベクトル** に格上げする。

| 特徴 | 内容 | 実現手段（標準APIのみ） | 表現上の効き目 |
|---|---|---|---|
| 聴感帯域 | 対数/メル/Bark 帯域（例: 32〜64帯）、float精度 | 既存 `js/fft.js` を worklet で常用 | 低域が“効く”見た目に。レイヤー分割を聴感等分に |
| オンセット | スペクトラルフラックス（帯域別） | 同上 | キック・スネア・ハイハットを分離して反応 |
| テンポ・拍位相 | BPM推定 + 位相追従（PLL） | オンセット自己相関 | **拍“前”に動ける**（予測）、拍同期回転・切替 |
| 小節頭 | ダウンビート推定 | 拍位相 + 低域アクセント | 4拍ごとのシーン切替 |
| 構造 | セクション境界（イントロ/ビルド/ドロップ等） | **オフライン時のみ**: 自己類似行列 + ノベルティ曲線 | 曲の展開に合わせた演出 |
| ステレオ | L/R 差・位相相関・定位 | `ChannelSplitterNode` | 左右に広がる表現、真のリサージュ |
| 音色 | スペクトル重心・平坦度・ロールオフ | FFT 派生量 | 明るい音→明るい色、ノイズ→粒子 |
| 調性 | クロマ（12音）・推定キー | FFT → ピッチクラス集約 | キーに応じた色相（音→色の共感覚マッピング） |
| ラウドネス | 短期ラウドネス（LUFS近似）・ダイナミクス | K特性フィルタ（BiquadFilter） | 音量差に依らない安定した反応（自動ゲイン） |

**設計原則**
- **単一経路**: ライブ再生もオフライン書き出しも同じ AudioWorklet + 同じ特徴抽出コードを通す（Phase 9.2 の worklet 資産を拡張）。→「プレビュー＝書き出し」をコードで保証。
- **二段階解析**: ライブは因果的（過去のみ）、ファイル再生時は **読み込み直後にバックグラウンドで全曲を先行解析**し「ソングマップ」（拍グリッド・構造・ラウドネス曲線）を作る。以後ライブ再生でも“未来を知った”演出が可能になる（既存オフライン解析の転用）。
- **後方互換**: `frame.freq` / `frame.time` / `frame.beat` は従来通り提供。既存14レンダラーは無改修で動く。新特徴は `frame.features` に追加。

### 4.2 繋ぐ — モジュレーション・マトリクス

シンセサイザーの発想を持ち込む。**任意の MFS 特徴 → 任意の設定パラメーター** を、量・カーブ・スムージング付きで結線する。

- 例: `キック強度 → 残像強度 (+30%)`、`拍位相 → 回転角`、`スペクトル重心 → 色相 (±40°)`、`セクション=ドロップ → 粒子量 ×2`
- 既存パラメーター（hue, sensitivity, density, motionSpeed …）が全部ターゲットになるため、**新レンダラーを作らなくても表現の組合せ数が桁違いに増える**
- プリセット（Phase 8 の JSON 入出力）に結線情報を含める → 作品の“振る舞い”ごと保存・共有できる
- UI は「結線一覧＋追加ボタン」だけに留め、C5（UI簡素）を守る。上級者向けは折りたたみ

### 4.3 描く — WebGL2 表現エンジン

- **WebGL2 レンダラー層を追加**し、Canvas 2D は互換フォールバックとして維持（契約は同じ `render(ctx, canvas, frame, settings)` 系で、`backend: 'webgl2'` を宣言するだけ）
- **ポストFXチェーン**（全タイプ共通に後段で適用）: ブルーム、フィードバック（前フレームの変形再投入＝残像の上位互換）、万華鏡、色収差、フィルムグレイン。すべて GLSL を JS 文字列で持つ（ビルド不要・ライブラリ不要）
- **GPU 粒子**: 10万粒子規模（Canvas 2D の数十倍）をビートで駆動
- **シーン合成**: 複数タイプを重ね、それぞれ異なる帯域/特徴に紐付け（既存「レイヤー」概念の一般化）
- **背景**: 黒/白固定（C6）を維持。発光系表現は黒背景で映え、白背景では減算系ブレンドに自動切替

### 4.4 演じる — 自動演出（Auto Director）とライブ操作

**(a) 自動演出** — このリポジトリ最大の差別化候補
- ソングマップの構造境界・小節頭で、プリセット/タイプを **拍ぴったりに** 切り替える
- ビルドアップ区間では徐々に密度・速度を上げ、ドロップの瞬間にフラッシュ → 新シーン
- 3スロット再生キューと組み合わせると、**曲を入れて再生するだけで VJ 作品が成立**する
- オフライン書き出しでも同一の決定的演出 → 「ファイルを入れて書き出すだけで MV ができる」

**(b) ライブ操作（パフォーマンス）**
- Web MIDI API で MIDI コントローラーのノブ/パッドをパラメーター・シーンに割当（MIDIラーン）
- A/B 2シーンのクロスフェーダー、タップテンポ、フラッシュ/フリーズ等のワンショット
- マイク入力（Phase 8）と合わせ、ライブ会場の VJ 用途に到達

**(c) タイムライン（録画モード強化）**
- ソングマップ上にキーフレーム（シーン・パラメーター）を置ける簡易タイムライン
- 自動演出の結果をタイムラインに“焼いて”手で微修正 → 書き出し

### 4.5 届ける — 出力の進化

| 項目 | 内容 | 備考 |
|---|---|---|
| 高解像度/高fps書き出し | 4K・60fps（オフライン経路は実時間非依存なので可能） | エンコーダー対応に依存 |
| 縦型 9:16 | ショート動画向け | **C7 の拡張 → 要判断（D3）** |
| シームレスループ書き出し | 指定区間を始点=終点でループ化 | SNS 向け |
| 3スロット一括書き出し | キューをまとめて順番に書き出し | 既存キュー資産の転用 |
| テキスト/タイトル焼き込み | 曲名・アーティスト名・歌詞タイミング（LRC 読込） | Canvas テキストで実装可 |
| PWA 化 | Service Worker でオフライン起動・インストール可能 | ビルド不要。C1 をむしろ強化 |
| URL 共有 | プリセット＋結線を URL ハッシュに圧縮（`CompressionStream`） | サーバー不要 |

### 4.6 基盤 — 進化を支える土台

- **テストのリポジトリ内収容**: `log.md` に記録された Node 単体・Chromium E2E スクリプトを `tests/` に正式配置。実行は開発者のみ（利用者には一切要求しない＝C1維持）
- **ゴールデンフレーム回帰**: オフライン経路の決定性を利用し、固定音源 → 指定フレームのピクセルハッシュを比較。全タイプの見た目の回帰を自動検知
- **MFS 精度テスト**: 既知 BPM のクリック音源・既知キーのサイン波合成で、テンポ/位相/キー推定の誤差を数値で検証
- **性能予算の計測**: フレーム時間を記録するデバッグオーバーレイ（`?debug`）

## 5. ロードマップ案（Phase 15〜）

依存関係順。各フェーズは単独でユーザー価値が出る単位に切っている。

| Phase | 名称 | 主内容 | 価値 | 工数感 | リスク |
|---|---|---|---|---|---|
| 15 | 基盤整備 | テスト収容、ゴールデンフレーム回帰、デバッグ計測 | 以降の全改修の安全網 | S | 低 |
| 16 | MFS v1（聴く） | 単一 worklet 経路、聴感帯域、帯域別オンセット、ステレオ、ラウドネス自動ゲイン、テンポ/拍位相 | 全タイプの“ノリ”が即改善 | L | 中（ライブ経路置換） |
| 17 | モジュレーション（繋ぐ） | 結線マトリクス、プリセット/JSON拡張、URL共有 | 表現の組合せ爆発 | M | 低 |
| 18 | ソングマップ＋自動演出（演じる a） | 先行全曲解析、構造推定、拍同期シーン切替、オフライン書き出し連動 | **最大の差別化** | L | 中（構造推定精度） |
| 19 | WebGL2 エンジン（描く） | GL バックエンド、ポストFX、GPU粒子、2Dフォールバック | 表現力・性能の天井突破 | L | 中（2系統保守） |
| 20 | パフォーマンス（演じる b/c） | Web MIDI、A/Bクロスフェード、タップテンポ、簡易タイムライン | VJ/制作ツール化 | M | 低 |
| 21 | 出力強化（届ける） | 4K/60、ループ、一括書き出し、テキスト焼き込み、PWA | 配信・SNS 実用 | M | 低〜中 |

**推奨の最短価値ルート**: 15 → 16 → 18（自動演出）。この3つで「曲を入れるだけで、拍と展開に合った映像が出て、そのまま書き出せる」という一段上の体験が完成する。WebGL2（19）は表現力の天井突破だが、既存 Canvas 2D の14タイプでも自動演出の価値は成立するため後回しで良い。

## 6. 各フェーズのテスト設計（要約）

| Phase | 自動テスト | 合格基準（案） |
|---|---|---|
| 15 | ゴールデンフレーム（14タイプ × 黒/白 × 16:9/1:1） | 既存出力とハッシュ一致 |

| 20 | MIDI メッセージのモック注入 | 割当・学習・保存の往復 |
| 21 | 4K/60 書き出しの構造検証（マクサー既存テスト拡張）、ループ継ぎ目のピクセル差 | 再生可能・シーク可能・継ぎ目差分ほぼ0 |

## 7. やらないこと（コンセプト保護のための明示的除外）

- npm パッケージ・バンドラー・トランスパイラーの導入
- サーバー必須機能（アカウント、クラウド保存、サーバーサイドレンダリング）
- 外部 ML モデル/ライブラリ依存の解析（音源分離・歌詞自動認識など）。標準 API の信号処理で届く範囲に限定する
- UI の多機能化による主役（ビジュアル）の圧迫。上級機能はすべて折りたたみ・既定オフ
- 背景の任意色化（C6）

## 8. オーナー判断事項

| # | 論点 | 選択肢 | 推奨 |
|---|---|---|---|
| D1 | 「外部ライブラリなし」の解釈 | A: ブラウザ標準APIは全て可（WebGL2/Web MIDI/SW 等） / B: 現行API範囲に限定 | **A**（利用者負担ゼロという本質は維持される） |
| D2 | 進化の主軸 | A: 自動演出（聴く→演じる） / B: 表現力（WebGL2） / C: ライブVJ（MIDI） | **A**（既存の決定的書き出し資産を最大活用、差別化が最大） |
| D3 | 縦型 9:16 の追加 | 追加する / しない | 追加（C7 は「対応」であり「限定」ではないと解釈。SNS 需要大） |
| D4 | ライブ解析経路の置換 | A: worklet へ一本化 / B: AnalyserNode 併存 | A（プレビュー＝書き出しの保証）。ただし Phase 16 内で旧経路をフォールバック保持 |
| D5 | テストの配置 | リポジトリ内 `tests/`（開発者専用） / 現状どおり外部 | リポジトリ内 |
| D6 | 着手範囲 | 推奨ルート（15→16→18）/ 全体 / 部分選択 | 推奨ルートで開始し、各フェーズ完了時に再判断 |

判断後、選択されたフェーズごとに `doc/plan-phaseXX.md` を作成し、`doc/spec.md` へ反映してから実装に入る。
