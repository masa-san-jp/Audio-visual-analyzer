## 1. 定義

### 1.1 超進化
このアプリを「パラメーターをいじるアナライザー」から、**曲を入れると、その曲のための映像作品が上演・書き出しされるエンジン**に変える。

### 1.2 圧倒的なビジュアル体験（描写そのものの 6 条件）
「アナライザーに見えない」「UI を隠す」は条件ではない。**描かれる絵そのもの**が次の 6 条件を満たすこと。
1. **光が本物に見える**
   - HDR の明暗差により、闇の中の光が実際にまぶしく見える
   - 体積のある光の筋、発光のにじみ、影、遮蔽による陰り
   - 屈折と集光（コースティクス）
2. **巨大なスケールと細部が同時にある**
   - 画面全体のうねりから一粒の粒子まで、あらゆる大きさに構造がある
   - 近づくと、その奥にさらに細部がある（フラクタル的な深さ）
3. **奥行きと空間がある**：霧の層・視差・被写界深度で、画面の向こうに広大な空間を感じさせる
4. **動きに物理の説得力がある**
   - 流体の渦・慣性・衝突・崩壊が、物理として正しく動く
   - 60fps で途切れず、モーションブラーがある
5. **音と絵が完全に一致する**
   - 音のすべての出来事に、その大きさに見合った視覚の結果が 1 フレーム以内に起きる
   - 静寂は本当に暗く静かにし、爆発は画面のすべてを変える（時間方向の明暗差を最大化する）
   - 曲を先に全部知っているので、ドロップの前に溜め（伏線）を作れる
6. **1 曲を通して見飽きない**：同じ絵を繰り返さず、曲の進行とともに世界の状態が変わり続ける

### 1.3 合格基準（試作で計測する）
| ID | 基準 |
|---|---|
| W-1 | 明るさの幅：1 フレーム内の輝度比（HDR、トーンマップ前）≥ 1000:1 |
| W-2 | 細部の量：下記の計測法で、低・中・高の各帯のエネルギーがいずれも 3 帯合計の 10% 以上（計測対象: 曲中の各セクション中央の 1 フレーム） |
| W-3 | 物量：粒子 ≥ 262,144（512×512）。流体と SDF レイマーチングの立体を同時に描く |
| W-4 | 同期：MFS のオンセット・拍イベントから視覚反応（該当 uniform の変化）までの遅れ ≤ 1 フレーム |
| W-5 | 時間方向の明暗差：ドロップ直前 1 拍（静寂）とドロップ直後 0.25 秒の画面平均輝度の比 ≥ 10 |
| W-6 | 境界：ソングマップの全セクション境界で境界イベントが発火する（100%） |
| W-7 | モチーフ：同じラベルのセクションで同じ形態 ID が選ばれ、2 回目以降は変奏番号が増える |
| W-8 | 性能：1920×1080 で描画時間 p95 ≤ 16ms（開発機 macOS、ヘッド付き Chrome） |
| W-9 | `file://` で直接開いて動き、外部ライブラリを使わない（WebGL2 はブラウザ標準 API。不変条件 C1・C2 の範囲） |

**W-2 の計測法**
1. 1920×1080 の最終出力（トーンマップ後の sRGB）を読み出し、輝度 Y = 0.2126R + 0.7152G + 0.0722B（0..1）に変換する
2. 4×4 の平均で 480×270 に縮小し、画像 L とする
3. G(σ) を、σ ピクセルのガウスぼかし（端は折り返し）とする。各帯を次のように取り出す
   - 高帯 H = L − G(1)L
   - 中帯 M = G(1)L − G(4)L
   - 低帯 Lo = G(4)L − mean(L)（平均値（DC）は除く）
4. 各帯のエネルギーを、画素値の二乗和とする。3 帯それぞれの比率が 10% 以上なら合格

**計測の細部の扱い**：計測の細部で本書に書いていない点は、実装者が妥当な方法を選んでよい。選んだ方法は `tests/world/measure.mjs` のコメントと log.md に記録する。本書の基準値は変えない（2026-10-04 アーキテクト決定）

ライブと書き出しの一致は、第 2 段階で扱う（§6）。

## 2. 試作の操作（評価用の最小限。定義の一部ではない）

1. `world.html` を開く。画面は黒く、中央に「曲をドロップ」とだけ出る
2. 音声ファイルをドロップすると、曲の解析（SongMapService）が走る。画面には解析中の小さな光の点だけが出る
3. 解析が終わると「クリックで開始」と出る。クリックで全画面になり、再生が始まる
4. 以後は操作パネルを一切出さない。マウスを 2 秒動かさないとカーソルも消える。`Space` で一時停止、`Esc` で全画面を解除、`?debug=1` で FPS・描画時間 p95・セクション・イベントのログを重ねて表示する
5. 曲が終わると世界は消滅して黒に戻り、「もう一度」とだけ出る

## 2.6 方針転換（2026-10-04 オーナー指摘を受けたアーキテクト決定。§2・§2.5・§3 より優先）

**A. UI**
- 最初から全画面で UI を出さない作り（§2）は誤りなので撤回する。
- ワールドモードは本体（`index.html`）の表示方式の 1 つとし、通常は既存 UI のプレビュー欄に描く。
- 全画面はボタンと `F` キーで切り替える。書き出しは常に全フレームの作品として出力する。
- 試作段階では `world.html` に、最小限の UI（ファイル読込・再生/一時停止・シーク・全画面ボタン）を常に表示する。

**B. 描写の範囲：抽象・流体・粒子・光に限定する**
- 具体物（岩・柱・建造物・地形・フラクタル建築）は描かない。
  - 理由 1：リアルタイムの具体物は安っぽく見える。
  - 理由 2：v5 の計測で、全画面の環境レイマーチングが GPU 時間 49ms の大半を占めた。
- 表現の型（レイヤー）は次の 4 つとする。
  1. **流体**：Stable Fluids による煙・インク・光の液体。染料は HDR の発光色。
  2. **粒子**：262,144 個以上。カールノイズや流体の速度場に乗る流れの線、銀河状の渦、火花、衝撃殻。速度方向に伸ばした発光の筋として描き、画面上の主役として**見える**こと（平均被覆 5〜25%）。
  3. **光**：リボン・軌跡・発光体と、それらのブルーム・にじみ・色収差。
  4. **フィードバック**：前フレームの変形・回転・縮小による残像、万華鏡、無限の反復。
- kind ごとの状態は次のとおり。
  - intro：静かな光の霧と、まばらな粒子
  - build：中心への収束と流れの加速。フィードバックによるトンネル化
  - drop：流体の爆発と粒子の大放出（相転移）、キックごとの衝撃殻
  - break：ゆっくりたゆたうインク
  - outro：散逸して消える
- `(kind, label)` による変奏の規則（§2.5）と、曲固有の 3 色パレットは維持する。
- 性能の目標：1080p で GPU p95 ≤ 16ms（W-8）。レイマーチングは使わないか、使う場合も小さな抽象の発光体に限る。

## 2.5 試作 v1 の評価と v2 の方向（2026-10-04 アーキテクト判定）

v1（画面中央に SDF の立体を 1 つ置き、周りに流体・粒子・光を重ねる構成）は**不合格**とする。理由は次のとおり。
- 全セクションで構図が同じ。中央に物体があるだけで、スケールも空間もない
- ドロップで画面全体が白飛びしてのっぺりする。グレインが強く、絵が濁る
- 26 万個の粒子が、まばらな点にしか見えない
- 表面の模様が安っぽい
- 2 回目のドロップが 1 回目と同じ

**v2 の原則（§3 より優先する）**
1. **画面全体を空間にする**
   - 物体を見せるのではなく、全画面のレイマーチングで「果てのない環境」を描き、カメラがその中を進む
   - 前景・中景・遠景の 3 層があり、遠景は霧に溶ける
   - 環境は少なくとも 4 種類用意する。例：反復する柱と光の大聖堂（ドメインの反復）、フラクタルの構造体（Mandelbox／KIFS）、果てしない地形（ノイズの高さ場）、光のトンネルや渦
2. **世界は kind ごとに別物にする**
   - intro は「虚空」、build は「トンネル（収束・加速）」、drop は「爆発した大空間（フラクタルの崩壊と再構成）」、break は「霧の大聖堂」、outro は「崩れて塵になる」
   - 世界（環境）は kind で選ぶ。再登場の判定は `(kind, label)` の組で行い、同じ組の n 回目は変奏番号 n とする。変奏番号に応じて、スケール・色・構造の複雑さ・カメラの速度を明確に変える（2 回目のドロップは 1 回目より明らかに大きく強く）。ラベル単位の形態 ID・パレット回転の決め方（§4）はそのまま残し、環境の中で使う（2026-10-04 アーキテクト決定。label A が複数の kind にまたがる場合の矛盾を解消）
3. **粒子は主役の物質にする**
   - 粒子は光の雨・塵・火花として画面全体を満たし、HDR の加算発光で明確に見えるようにする
   - 粒子はカメラ空間の 3D 位置を持ち、奥行きに応じてサイズとぼけを変える
4. **露出と色を設計する**
   - 自動露出の目標値を設け、白飛びは画面の 2% 以下に抑える
   - 黒は深く保ち、ACES の後にコントラストと彩度を調整する
   - グレインは控えめにする（σ ≤ 0.015）
   - パレットは曲ごとに主色・補色・アクセントの 3 色に限り、濁らせない
5. **表面の質感**：プロシージャルな細部（fbm の法線摂動、エッジの発光、AO、ソフトシャドウ）を、画面の解像度に見合う細かさで描く。粗い格子や等高線のような模様は出さない
6. **カメラ**
   - 進む・回り込む・カットする。カメラの経路は環境ごとに設計する
   - ビルドでは前進を加速し、ドロップの瞬間に視点を大きく変える

## 3. 世界の構成（レイヤー）

すべて WebGL2 で描く。`js/world/` に置く classic script とする（ガイド §9.1 の規約に従う）。

| 層 | 内容 | 音楽との結びつき |
|---|---|---|
| 媒質（Medium） | GPU 上の 2D 流体シミュレーション（Stable Fluids：速度・圧力・染料の各テクスチャ。解像度は画面の 1/4〜1/2）。煙やインクのような媒質で、画面全体を満たす | 低域のオンセットで中心から放射状の力を加える。ベース帯域のエネルギーで渦度を注入する。セクションの種類で粘性と減衰を変える |
| 物質（Matter） | 512×512 = 262,144 個の GPU 粒子（位置と速度をテクスチャに持ち、ピンポン更新）。媒質の速度場とカールノイズに乗って動き、加算合成の発光点として描く | 高域帯域とオンセットで輝度を上げる。拍の位相で粒子サイズを脈動させる。ビルドでは中心の引力を強め、ドロップで斥力に反転させて爆散させる |
| 構造（Form） | 画面中央のレイマーチング SDF 形態（ポリゴンを使わない）。形態は数式の族から選ぶ（多面体・トーラス結び目・フラクタル・メタ球など、6 種以上）。ソフトシャドウ、アンビエントオクルージョン、ガラス状の屈折と分散（虹色のにじみ）、内部発光をシェーダーで計算する | セクションのラベルで形態 ID が決まる。和音（クロマ）で変形パラメータが動く。ラウドネスで脈打つ |
| 光（Light） | 描画はすべて HDR（RGBA16F の浮動小数点バッファ）で行う。構造の内部光源、体積のある霧と光の筋（ゴッドレイ）、多段ブルーム、被写界深度、モーションブラー（速度バッファによる）、色収差、フィルムグレイン、ACES トーンマップ、セクションごとの色調整 | ドロップでブルームと露出が瞬間的に跳ね上がる。曲全体の和音分布から、その曲固有のパレット（主色・補色）を決める |
| カメラ（Camera） | 構造の周りを動く仮想カメラ（距離・角度・揺れ）。流体と粒子は 2D の奥行き表現と視差で合わせる | イントロはゆっくり漂う。ビルドではドリーインで圧縮する。ドロップでは小節頭ごとにカット（角度を不連続に変える）。ブレイクでは静止に近づける |

## 4. 物語の設計（ソングマップ → 演出）

ソングマップ（Phase 18 §4.3）の `sections[].kind` と `label` から、曲全体の物語を事前に組み立てる（`compileWorldScore(songMap, seed)`）。

| kind | 世界の状態 | 境界イベント（セクション開始時） |
|---|---|---|
| `intro` | 闇の中に一点の光。粒子はまばらに漂い、媒質は静か | 光が点る |
| `build` | 収束と圧縮。セクション内の進み具合 p（0→1）に比例して、粒子の中心への引力・減光・カメラの接近・画面の揺れが増す | 媒質の流れが中心へ向かい始める |
| `drop` | 解放。セクション内は高エネルギーで、キックごとに衝撃波を出し、小節頭でカットする | **相転移**：媒質へ全方位の衝撃波、粒子の斥力への反転と爆散、ブルームと露出の跳ね上がり、形態の位相変化、パレットの反転（主色と補色の入れ替え） |
| `break` | 余韻。時間の流れを 0.3 倍に落とし、霧が濃くなる。形態は溶けかける | 粒子が慣性で漂いはじめる |
| `outro` | エントロピー。全体が塵になって減衰し、最後は黒 | 光源が消え始める |
| `main` | 中くらいのエネルギーで安定。モチーフを見せる | 形態の切り替え |

- **モチーフと変奏**：ラベルごとに形態 ID とパレットの回転量を決める（ラベル文字列とシードのハッシュによる）。同じラベルの n 回目の出現では変奏番号 n を使い、強度・粒子密度・形態の複雑さを上げる（W-4）
- **先読み（伏線）**：次のセクションが `drop` のとき、残り 2 小節から画面の周辺を減光し、媒質の動きを止める。ドロップ直前の 1 拍は完全な静寂にする。曲全体を先に知っているこのアプリだけができる演出として、最も重要
- 境界イベントは `score.events[]`（`{ tSec, type, sectionIndex }`）として事前に全件を持つ。ライブでは時刻が通過したら発火し、`?debug=1` のログに出す（W-2 の計測）

## 5. 実装の構成（試作）

| ファイル | 役割 |
|---|---|
| `world.html` | 試作の入口（`index.html` とは別ページ。既存アプリには触れない） |
| `js/world/gl-util.js` | WebGL2 の補助（シェーダーのコンパイル、FBO・テクスチャ、ピンポン、全画面三角形） |
| `js/world/fluid.js` | 媒質（Stable Fluids） |
| `js/world/particles.js` | 物質（GPU 粒子） |
| `js/world/form.js` | 構造（SDF レイマーチング、形態の族） |
| `js/world/post.js` | 光と仕上げ（ブルーム、ゴッドレイ、色収差、グレイン、トーンマップ、色調整） |
| `js/world/score.js` | `compileWorldScore`（§4）とパレット決定。純関数で決定的にする |
| `js/world/world-engine.js` | 上の各層を組み合わせ、毎フレーム `render(tSec, features, dt)` する |
| `js/world/world-app.js` | ページの制御（ドロップ、解析、全画面、再生、debug） |

- 解析は既存資産を使う：`AudioEngine`（ライブの MFS 特徴量）と `SongMapService`（ソングマップ）。読み込み順は `index.html` に合わせる
- 毎フレームの経路では配列やオブジェクトを新規生成しない（ガイド §9.3）。uniform 値は事前に確保した型付き配列に書く
- 乱数は `makeRng(seed)` と、シェーダー内のハッシュ関数だけを使う
- WebGL2 が使えない環境では「この環境では利用できません」と表示する

## 6. 第 2 段階（試作の評価後）

- 書き出し：流体と粒子は状態を持つため、書き出しでは固定 dt（1/fps）で同じ順序でステップする。ライブも固定 dt のサブステップで進め、同じ曲・シードで同じ作品になるようにする
- 本体（`index.html`）への統合、自動演出との統合、形態とパレットの語彙拡張（形態 30 種以上、媒質・粒子・光の振る舞いの部品化）
- 音源分離（楽器ごとの役者）による、さらなる表現の分化
