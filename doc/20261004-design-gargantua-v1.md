# GPU アナライザー詳細設計：`g-gargantua`（ブラックホール）v1（Opus 設計・Codex 実装）

- Date: `2026-10-04`
- 位置づけ: このタイプの見た目・数式・定数の唯一の正（SSOT）。実装者は書かれたとおりに実装する。
- 目標: 映画『インターステラー』のガルガンチュアに匹敵する、宇宙の壮大さと美しさ。
- 設計の 3 原則（オーナー評価から導いたもの）
  1. **因果が読める**：画面で起きる変化は、すべて音楽の具体的な出来事と 1 対 1 に対応させる。意味の分からないパルス・リング・波紋は入れない。
  2. **階層**：主題（ブラックホールと降着円盤）・副題（光子リングとホットスポット）・背景（重力で歪む星空）を、明るさ・鋭さ・動きの速さで明確に分ける。
  3. **瞬き**：粒や星は、ちらつかせない。星のように煌めかせる（ゆっくりした明滅と、回折の光条）。
- 構想 §2.8 の更新: `g-rings` は削除する（オーナー評価「不要」）。`g-galaxy` は本タイプに置き換える。

## 1. 描画方式：重力レンズの光線追跡

- 全画面のフラグメントシェーダーで描く。**半解像度**（960×540）で計算し、双線形補間で拡大したあと、既存の post（ブルーム・ACES）を通す。
- 単位：シュワルツシルト半径 `Rs = 1`。

### 1.1 カメラ

- 位置は球座標 `(dist, inc, azim)` で、ブラックホールを注視する。上方向は (0,1,0)。
- 視野角 `FOV = 38°`。
- 円盤は y = 0 の平面にある。`inc` は円盤面からの仰角。

### 1.2 光線の積分

ピクセルごとに 1 回行う。シュワルツシルト時空の光の測地線を、デカルト座標で近似する（よく知られた h² 法）。

```
pos = camPos;  dir = normalize(rayDir)
h2  = dot(cross(pos, dir), cross(pos, dir))      // 角運動量の二乗（保存量）
for i in 0..MAX_STEPS(=180):
    r   = length(pos)
    if r < 1.0: hitHorizon; break                 // 事象の地平面 → 真っ黒
    dt  = clamp(r * .045, .015, 1.6)              // 近いほど細かく刻む
    acc = -1.5 * h2 * pos / pow(r, 5.)            // 光の曲がり
    prev = pos
    dir += acc * dt;  pos += dir * dt             // 速度は正規化しない（h² 法の流儀）
    if sign(prev.y) != sign(pos.y):               // 円盤面の通過
        hitPoint = 補間で y = 0 になる点
        rd = length(hitPoint.xz)
        if 3.0 <= rd <= 14.0:                     // 内縁 = ISCO 3Rs、外縁 14Rs
            accumulate disk sample (§2)。透過率 alpha を減らす（最大 3 回まで通過を許す）
    if r > 60.: escaped; break
```

- 地平面に吸い込まれた光線は黒（0）。
- 逃げた光線は、最後の `dir` の向きで背景（§4）を引く。
- 円盤のサンプルは、前から順に合成する：`col += alpha * sampleColor * sampleOpacity;  alpha *= 1 - sampleOpacity`。
- こうすると、**円盤の向こう側が穴の上下に回り込んで見える像**と**光子リング**が、物理的に自然に現れる。

## 2. 降着円盤（主題）

円盤上の点の極座標 `(rd, φ)` での発光を、次のように計算する。

```
// ケプラー回転：内側ほど速い
Ω     = .45 * pow(rd / 3., -1.5) * motionSpeed       // rad/s
φrot  = φ - Ω * t

// 温度と色（黒体放射ふう。内側ほど高温で白く、外側ほど橙から赤へ）
T     = pow(rd / 3., -.75)                           // 1 → 約 0.33
base  = blackbodyRamp(T)                             // §2.1
// パレット（WORLD_PALETTES[dominantChroma]）を 20% だけ混ぜて、曲ごとの色味を出す
tint  = mix(base, base * palette.primary * 1.6, .2)

// 細部：渦巻き状の乱流（細い弧の筋）
q     = vec2(log(rd) * 6.0, φrot * 3.0)
turb  = fbm(vec3(q.x * 2.2, q.y + q.x * .8, t * .05))   // 4 オクターブ
fil   = pow(turb, 2.2) * 1.6 + .25

// 半径方向の包絡：内縁で鋭く立ち上がり、外縁でなめらかに消える
env   = smoothstep(3.0, 3.25, rd) * (1. - smoothstep(10.5, 14.0, rd))

// ドップラー増光（左右の明暗差。ガルガンチュアに合わせて控えめにする）
v     = sqrt(.5 / rd)                                // 円盤の速度（光速比）
beam  = pow(1. / (1. - v * dot(tangent(φ), -viewDir)), 2.2) を [.45, 2.2] にクランプ

I_disk = env * fil * beam * (.35 + 1.4 * pow(3. / rd, 2.))  // 内側ほど明るい
sampleColor   = tint * I_disk * musicGain(rd)        // §3
sampleOpacity = clamp(env * (.55 + fil * .35), 0., .95)
```

### 2.1 `blackbodyRamp(T)`（線形 RGB。T は 0.33〜1）

| T | RGB |
|---|---|
| 0.33 | (1.00, 0.28, 0.05) |
| 0.50 | (1.00, 0.52, 0.18) |
| 0.70 | (1.00, 0.78, 0.48) |
| 0.85 | (1.00, 0.92, 0.80) |
| 1.00 | (0.95, 0.97, 1.00) |

区間ごとに線形補間する。

## 3. 音楽との対応（因果を 1 対 1 にする）

| 音楽の出来事 | 画面の変化 | 式 |
|---|---|---|
| **32 帯域の音量** | 円盤を 32 本の同心の帯に分け、各帯の明るさを帯域の音量で決める。円形アナライザーを宇宙の規模にしたもの | 帯の番号 `k = floor((rd - 3.) / 11. * 32.)`。**外側 = 低域、内側 = 高域**（`band = 31 - k`）。`musicGain(rd) = .45 + 2.2 * L[band]`。隣の帯とは帯幅の 15% だけなめらかに補間する |
| **キック**（低域オンセット） | 円盤の内側 1/3 が、キックと同時に発光する | `kickEnv = exp(-age/.11)`。`rd < 6.5` の部分の `musicGain` に `× (1 + 1.8 * kickEnv * smoothstep(6.5, 3., rd))` を掛ける |
| **高域オンセット**（ハイハット等） | ① 背景の星がきらめく ② 円盤上に光の点（ホットスポット）が生まれて周回する | ① §4 の星の明滅位相を進める。② 最大 12 個のホットスポットを持ち、オンセットごとに 1 個を `rd = 3.5〜8` の決定的な位置に生む。寿命は 6 秒。点はケプラー回転し、ガウス半径 0.18Rs、HDR の明るさ 6 で減衰していく |
| **ラウドネス**（短期） | 全体の露出 | `exposure *= .85 + .3 * loudnessNorm` |
| **セクションの種類** | カメラの距離・仰角・周回速度（下表）。切り替えは 4 秒かけてイーズする | |

| kind | dist | inc | 周回速度 azim'（rad/s） | 円盤の明るさの係数 |
|---|---|---|---|---|
| intro | 40 → 26（セクション内で近づく） | 4° | .010 | .6 |
| build | 26 → 18 | 4° → 9° | .020 → .05 | .8 → 1.1 |
| drop | 15 | 7° | .07 | 1.35 |
| break | 30 | 14° | .012 | .7 |
| outro | 26 → 60（遠ざかる） | 4° | .008 | .9 → 0 |
| main | 22 | 6° | .03 | 1.0 |

- **禁止**：拍ごとの全画面パルス、同心円の衝撃リング、意味のない波紋、ランダムなフラッシュ。
- 2 回目のドロップ（同じ `(kind, label)` の変奏番号が 2 以上）では、dist を 13 に、周回速度を .09 に変え、円盤の明るさの係数を 1.5 倍にする。

## 4. 背景（重力で歪む星空）

- 背景は、逃げた光線の向き `d` から計算する。そのため重力レンズで歪んで見える。
- **星**：方向を立方体マップ風のセルに分ける（`cell = floor(d * 180.)`）。
  - 各セルに、確率 3% で星を 1 つ置く。
  - 明るさは `pow(hash, 18.) * 6.`。色は少し青白から橙までのランダム（ハッシュで決める）。
  - 星は点として描く。半径は 0.6 画素相当。
  - **明滅**：`twinkle = .75 + .25 * sin(phase_star + highOnsetPhase * 1.7)`。`highOnsetPhase` は高域オンセットのたびに +1 する。
  - 明るい星（上位 0.5%）だけ、細い回折の光条（4 方向・長さ 6 画素）を付ける。
- **淡い天の川**：大きなスケールの fbm を 2 層重ねる。明るさは ≤ 0.015。色は `palette.secondary * .4`。
- 背景の明るさの上限は ≤ 0.04。主題より常に 1 桁以上暗くする（階層）。

## 7. v1.1 改訂（2026-10-05 オーナー評価と Opus の判定を反映。§1〜§6 より優先）

### 7.1 円盤の継ぎ目の根本修正と 2 層化
- **継ぎ目の原因**：fbm の入力に `φrot * 3.0` を直接使っていたため、φ = ±π の折り返しで不連続になっていた。
- **修正**：方位角は周期的な座標で与える。`a = vec2(cos(φrot), sin(φrot)) * 3.0` とし、`turb = fbm(vec3(log(rd)*6. + a.x*.6, a.y*.6 + log(rd)*.8, t*.05) + vec3(a, 0.))` のように、cos/sin を通して入力する（φ に関して連続になること）。
- **2 層の円盤**：円盤面の上下に、`y = ±0.035` の 2 枚の薄い層として描く（光線の通過判定もそれぞれで行う）。
  - 層 A：上記の式で、回転は Ω × 3.0。
  - 層 B：fbm の空間スケールを 1.7 倍、位相オフセットを 2.1 にし、回転は Ω × 4.2（A とずらすことで模様を常に流す）。
  - 不透明度はそれぞれ 0.6 倍にする。2 層の合成で、筋が交差して奥行きのある渦の流れに見えるようにする。
- 回転速度：§2 の Ω に、全体で × 3.0 を掛ける（係数 0.45 を 1.35 にする）。

### 7.2 露出と、白飛びの抑制
- 円盤の強度 `I_disk` に掛ける基準の係数を、0.55 倍にする。
- `fil` を `pow(turb, 3.0) * 2.2 + .08` に変える（暗い隙間を深くする）。
- ドロップで寄ったときも、画面の 8% 以上が白飛びしないこと。白飛びの判定は、トーンマップ後の輝度 ≥ 0.97。

### 7.3 キックを見える化する
- キック発光の係数を 1.8 から 2.6 にする。
- トーンマップの手前で頭打ちにならないように、基準の露出を下げる（7.2）。そのうえで、画面上のキック直後 0.1 秒の内側円盤の輝度が ≥ 35% 上がること（G-kick を画面の値で判定する）。

### 7.4 光子リングのちらつき
- 影の縁の近く（光線の最接近距離が 1.3〜3.2Rs）の画素だけ、2×2 のサブサンプルで光線を 4 本追跡し、平均する（他の画素は 1 本のまま）。

### 7.5 背景の星を見やすくする
- 星の確率を 3% から 5% にする。
- 星を円盤状の発光点として描く。半径は 1.2〜2.6 画素（1080p 基準、明るさに比例）で、芯はガウス、外周に柔らかい光暈（半径 × 3、強さ 0.15）を付ける。
- 明るさは `pow(hash, 10.) * 9.`。背景の明るさの上限は、星の芯に限って 0.6 まで許す（星以外の背景は従来どおり ≤ 0.04）。
- 回折の光条は上位 2% に付ける。長さは 10〜18 画素、太さは 1 画素。
- 明滅は §4 の式のままにする（音の高域オンセットで位相が進む）。

### 7.6 空間の歪みを強く見せる（カメラと重力）
- **カメラの仰角を大きく変える**：§3 の inc の表を次に置き換える。どれも 4 秒でイーズする。
  - intro：2°
  - build：2° → 18°（進み具合に比例。持ち上がりながら近づく）
  - drop：1 回目は 4°、2 回目は −10°（円盤の下側から見上げる）
  - break：28°（上から見下ろすと、光子リングの形が大きく変わる）
  - outro：8°
- **ゆっくりした縦方向の揺れ**：inc に `+ 3° * sin(t * .07)` を加え、azim の周回と合わせて、レンズ像が常に形を変え続けるようにする。
- **ドロップでの重力の増強**（因果：ドロップ ＝ 重力の高まり）：
  - 光の曲がりの係数を、ドロップの間だけ 1.5 から 2.1 にする（質量を増やした近似）。開始時に 1.2 秒でイーズインし、終了時に 2 秒でイーズアウトする。
  - あわせて、事象の地平面の半径と円盤の内縁も、比例して 1.0 → 1.18、3.0 → 3.4 に広げる。
- **背景のレンズ像を見える化する**：天の川の帯を、画面の対角線に沿う 1 本の帯として置く。明るさは ≤ 0.035、細部は fbm 5 オクターブ。帯が穴の周りでアインシュタインリング状に曲がって見えることで、空間の歪みが読み取れるようにする。

### 7.7 受け入れ（追加分）
- 円盤の継ぎ目がない：φ = ±π の位置の左右 4 画素の輝度差が、周囲の平均差の 2 倍以下。
- 白飛び率 ≤ 8%（全時刻）。
- G-kick（画面）≥ 35%。
- 星：平均で画面あたり 400 個以上が 1.5 画素以上の大きさで見える。
- GPU p95 ≤ 16ms（7.4 の 2×2 サブサンプルを含む）。

## 8. v1.2 改訂（2026-10-07 Opus 判定。§7 の円盤の質感だけを修正する）

**判定**
- v1.1 では、星の視認性・継ぎ目の解消・レンズ像の変化はできている。
- 一方で、円盤が細かい斑点やモアレ（ざらつき）になり、v1.0 の絹のような筋の美しさが失われた。円盤全体も暗くなりすぎている。
- 原因：2 層化と `pow(turb, 3)` によって、画素より細かい高コントラストの模様が生まれ、半解像度で折り返し（エイリアシング）を起こしている。

**修正**
1. **画素の大きさに応じたオクターブの減衰（LOD）**
   - 光線が円盤に当たった点での、1 画素の大きさ `footprint = travel * pixelAngle` を求める。`pixelAngle = FOV / 540`（内部の解像度）。円盤座標に換算した `fp = footprint / rd`（角度方向）。
   - fbm の各オクターブ k（波長 λ_k）の重みに `smoothstep(2.0, 0.6, fp / λ_k)` を掛ける（画素より細かいオクターブを消す）。
2. **筋のコントラスト**
   - `fil = pow(turb, 1.8) * 1.5 + .18` にする（v1.0 と v1.1 の中間）。
   - 層 B の不透明度を 0.6 から 0.35 に下げ、層 A を主にする。
3. **明るさ**
   - §7.2 の基準係数 0.55 を 0.78 にする。
   - 白飛び率 ≤ 8% は引き続き守る。
4. **時間方向の安定化**
   - 円盤だけ、前フレームとの指数移動平均（係数 0.6）を取る。
   - 前フレームの位置は、円盤の回転（ケプラーの角速度）で逆算して参照する（再投影）。
   - 再投影の誤差が大きい画素（深度の差が 5% を超える）では履歴を捨てる。

**受け入れ**
- 円盤の高周波のちらつき：時間方向の画素の分散が v1.1 の 40% 以下。
- 見た目：v1.0（t=20、t=45）の滑らかな筋に近い。
- §7.7 の他の基準を維持する。

## 9. v1.3 改訂（2026-10-07 オーナー評価。§7.1 の 2 層円盤・§7.5・§8 を置き換える）

**オーナーの評価**
- 背景の星が大きすぎて、ブラックホールが小さく見える。星は最初の大きさでよい。
- 光のリングが薄い。大量の光が濁流のように流れていないと迫力がない。

**判定（Opus）**
- 薄い板として描く円盤（1〜2 層）では、量感も勢いも出ない。v1.2 のオクターブ減衰（LOD）でも、ざらつきは解消しなかった。

### 9.1 背景の星を v1.0 に戻す
- §7.5 を撤回し、§4（星の確率 3%、点の半径 0.6 画素、`pow(hash, 18.) * 6.`、光条は上位 0.5%）に戻す。
- 明滅（高域オンセットで位相が進む）と、対角の天の川の帯（§7.6）は残す。

### 9.2 厚みのある「光の濁流」としての降着円盤
- **体積として描く**：円盤は、厚みのある発光体（スラブ）とする。高さのスケールは `H(rd) = .10 + .045 * (rd - 3.)`（内縁 0.10Rs、外縁 0.6Rs ほど）。
- **光線の扱い**：§1.2 の光線積分のなかで、光線が `|y| < 2.2 * H(rd)` の範囲にある間は、刻み幅を `min(dt, H(rd) * .35)` に制限する。各刻みで発光と吸収を積分する：
  ```
  ρ        = exp(-(y / H)^2) * env(rd)                // 密度（中心面がいちばん濃い）
  emission = tint * I_flow * ρ * musicGain(rd) * dt
  col     += alpha * emission
  alpha   *= exp(-ρ * κ * dt)                         // κ = 1.6（不透明になりすぎない）
  ```
  2 層の板（§7.1 の層 A・層 B）は廃止する。
- **流れの模様（濁流）**：模様は、半径方向に細かく、方位方向に長く伸びた異方性のノイズで作る。方位の入力は §7.1 と同じく周期座標にする。
  ```
  a     = vec2(cos(φrot), sin(φrot))
  // 半径方向の波長は短く（筋が細かい）、方位方向は長く（流れに沿って伸びる）
  s(φo) = fbm(vec3(log(rd) * 18., (a.x*cos(φo) - a.y*sin(φo)) * 1.4, (a.x*sin(φo) + a.y*cos(φo)) * 1.4 + y * 3. + t * .2))
  // 流れ方向のモーションブラー：方位を少しずつずらした 6 点の平均（ざらつきも消える）
  flowTex = (1/6) Σ_{j=0..5} s(φo = -Ω * .045 * j)
  streak  = pow(flowTex, 1.4) * 1.8 + .25
  ```
- **明るさ（大幅に上げる）**：
  - `I_flow = streak * beam * (1.2 + 6.0 * pow(3. / rd, 2.2))`
  - 内縁付近の芯は HDR の輝度 6〜12（白く燃え、ブルームであふれる）。外縁は 0.3 程度。
  - 白飛び率の基準を ≤ 18% に緩める（迫力のため。ただし画面全体を白にはしない）。
  - §7.2・§8.3 の係数 0.55 / 0.78 は撤回する。
- **回転の速さ**：§7.1 の Ω × 3.0 を維持する。
- **円盤の色**：§2 の黒体放射のランプは、内側（T > .85）だけ、純白寄りの (1.0, .96, .9) に寄せる。
- **時間方向の安定化（§8.4 の EMA）**：撤回する（ブラーで足りるため。ゴーストも防げる）。
- **フットプリントによるオクターブ減衰（§8.1）**：残す。半径方向のオクターブだけに適用する。

### 9.3 帯域とキック（§3 の対応は維持する）
- 32 本の帯の明るさは、`musicGain(rd)` を通して体積の発光に掛かる。そのため帯域は、濁流の中の光の強弱として見える。
- キックは、内側 1/3 の体積発光を × (1 + 2.6 * kickEnv) にする。体積があるので、光の量の増加としてはっきり見える。

### 9.4 性能
- GPU p95 ≤ 16ms を維持する。
- 超える場合は、ブラーの点数を 4 に、fbm を 4 オクターブに下げてよい。それでも超える場合は、スラブ内の刻みを `H * .5` まで粗くしてよい。

### 9.5 受け入れ
- 円盤の上下の光の弧の太さ：t=45 で、光の弧の明るい部分（輝度 > 0.5）の太さが、影の半径の 35% 以上。
- 星の大きさ：v1.0 と同等（直径の中央値が 1.5 画素以下）。
- 白飛び率 ≤ 18%。G-kick（画面）≥ 35%。GPU p95 ≤ 16ms。
