### 2.1 IMP-00 仕様書の古い記述の整理

確認した食い違いのうち、影響が大きいもの:

| 重要度 | 仕様書の記述 | 実態 |
|---|---|---|
| 高 | §21 の受け入れ条件 8「背景が常に黒である」、§15.2「黒背景固定」 | §2.2・§11.1・§25 と実装はどれも「黒または白」 |
| 中 | §20・§23「Phase 19（WebGL2）は未着手」 | GPU タイプ3種は WebGL2 で実装済み（`js/world/gl-util.js:63`） |
| 中 | §4・§15.1「タイプは棒グラフ／円形放射」 | 2D 6種＋GPU 3種 |
| 中 | §11.4「どのタイプでも棒／波形線／点を選べる」 | スペクトログラムは選べない。3D地形・トンネル・リサージュは波形線／点だけ |
| 中 | §1.1「GPU の FPS は 30／60 から選ぶ」 | 画面の選択肢は 25／29.97／30 だけで、60 は選べない（§3 の判断 1） |
| 中 | §1.1「キー1〜3で GPU タイプを切り替える」 | 本体にこのキー操作はない。テスト用の画面にだけある（§3 の判断 2） |

このほか軽微なもの7件（実装済みの機能を「将来の拡張」と書いている、節番号の順序の誤り、など）。存在しないファイル・節への参照は0件、README は実装と一致していた。

### 2.2 IMP-01 使えない組合せの理由表示

入力（ファイル／マイク）×出力（プレビュー／リアルタイム録画／書き出し）で確認した結果:

- **2D タイプ**: すべての組合せで使える
- **GPU タイプ**: 次の3点が、理由を表示せずに挙動を変えている

| 組合せ | 現在の挙動 | 根拠 |
|---|---|---|
| ファイル×リアルタイム録画（解析が終わる前） | GPU 側の準備ができていないので 2D キャンバスを録るが、GPU 選択中は 2D を描かないため、**止まった画面が録られる**。エラーも出ない | `ui-controller.js:574`、`visualizer-core.js:163` |
| GPU 選択中にマイク開始・プリセット読込 | 直前の 2D タイプへ**表示なしで**戻る（タイプ一覧でマイク中に GPU を選べない件は、理由の表示がある） | `ui-controller.js:125`・`:1188-1193`・`:1217-1219` |
| 書き出しで FPS に 25／29.97 を選ぶ | **表示なしで** 30 fps になる | `world-bridge.js:187` |

1つ目は不具合と言えるので、IMP-01 の採否にかかわらず修正を推奨します。改善案の「全タイプ×5軸の能力表」は、2D がすべて対応済みなので、今は GPU の3点を直せば実質の効果はほぼ得られます。

### 2.3 IMP-02 周波数軸の対数化（Issue #68）

48kHz・FFT 2048・50Hz〜15kHz で計算した、画面幅に占める割合:

| 帯域 | 現行（線形） | 対数（提案式） |
|---|---|---|
| 50〜500Hz（低音域） | 3.0% | 40.4% |
| 1kHz までの左側 | 6.4% | 52.5% |

- 現在は棒グラフ・点・波形線・円形放射・トンネル・3D地形が線形です。スペクトログラムだけは独自の疑似対数（ビン番号で計算）です
- 注意点: 対数にすると 50〜100Hz に画面の 12% を割り当てますが、該当する周波数のデータは 2 本しかありません。補間・集約の方法を決めないと、低音域がブロック状に見えます
- レイヤー分割（均等／聴感）は別の機能で、変更しません

### 2.4 IMP-03 再現性の比較契約

既に検証済みのもの: 解析の決定性、ライブと書き出しで解析とタイムラインが一致すること、シーク、特徴量が無い場合（null）、AudioWorklet を強制的に無効にした場合。

不足しているもの:

1. ライブ表示と書き出しの**同じ時刻の画像**の比較（今はタイムラインまでしか比較していない）
2. 書き出しを途中で中止したあと、再実行した結果が一致すること
3. テストごとの条件（入力・設定・FPS・解析経路など）を記録する形式

不安定なテスト: 今回の全件実行（279件: 251成功・1失敗・27スキップ）で、B16-02m（マイク入力時の解析初期化）だけが失敗した。単独で2回実行すると2回とも成功したので、他のテストとの実行順か負荷に依存している。不安定なテストは外注の作業者が「自分の変更で壊した」と誤解する原因になるため、修正を推奨します。27件のスキップは GPU が無い環境のためで、正常です。

### 2.5 IMP-04 効かない設定の整理

動かしても描画が変わらないスライダー:

| タイプ | 効かない設定 | 根拠 |
|---|---|---|
| 棒グラフ・円形放射（表現方法が「棒」） | 粘性揺らぎ（効くのは波形線・点だけ） | `frame-pipeline.js:228-230` |
| スペクトログラム | 線の太さ・密度・基準点オフセット・残像強度・動画合成 | `spectrogram.js`、`frame-pipeline.js:95` |
| トンネル | 基準点オフセット | `tunnel.js` |
| リサージュ | スムージング・音量自動補正（波形だけを使うため） | `lissajous.js` |
| 解析が AnalyserNode に戻った環境 | 音量自動補正 | `frame-pipeline.js:120` |

利用者の設定を勝手に書き換える箇所:

- レイヤー非対応のタイプでレイヤー数が 1 に変わる（`ui-controller.js:1266`）
- 選べない表現方法が先頭の候補に変わる（`:1255`）
- 動画が無いと動画合成が OFF になる（`:447`）

改善案は「無効なときも保存値を保持する」としているので、この3か所は改善案と食い違います（§3 の判断 4）。効かないスライダーは、各タイプの能力宣言を細かくするだけで隠せます。

## 3. 判断をお願いしたい点

| # | 論点 | 選択肢 | 推奨 |
|---|---|---|---|
| 1 | GPU の書き出し FPS | A: 画面に 60 fps を追加する / B: 仕様書を「30 fps 固定」に直す | **A**（GPU 側は 60 に対応済みで、UI に選択肢を足すだけ） |
| 2 | 数字キー 1〜3 での GPU タイプ切替 | A: 本体にも追加する / B: 仕様書から削除する | **B**（既存のショートカットとの衝突を避けるため。必要なら後で追加する） |
| 3 | 周波数軸の既定値（IMP-02） | A: 既定を対数にする（Issue #68 の要望どおり。基準画像 26 件を更新） / B: 既定は線形のままで、対数を選べるようにする | **A**（効果が大きく、既存のプリセットは軸の設定を持たないので、読み込んだときは対数で表示されることを仕様に明記する） |
| 4 | 非対応タイプでの保存値の書き換え（IMP-04） | A: 保存値は保持し、描画時だけ無視する / B: 現行どおり書き換える | **A**（タイプを行き来しても設定が失われない。改善案の方針とも一致する） |
| 5 | GPU で解析が終わる前の録画（IMP-01） | A: 録画開始ボタンを無効にして理由を表示する / B: 解析が終わるまで待ってから録画を始める | **A**（挙動が分かりやすく、実装も小さい） |

### 3.1 決定結果（2026-11-15）

| # | 決定 |
|---|---|
| 1 | GPU の書き出しに 60fps の選択肢を追加する |
| 2 | 数字キー 1〜3 による GPU タイプ切替は仕様書から削除する（テスト専用画面の機能として残す） |
| 3 | 周波数軸の既定を対数にする |
| 4 | 非対応タイプでも保存値は保持し、描画時だけ無視する |
| 5 | GPU で解析が終わる前は録画開始ボタンを無効にし、理由を表示する |
