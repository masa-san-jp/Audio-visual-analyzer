# Audio Visual Analyzer 改善仕様案

- 状態: **提案 v0.1・未実装・未採用**（2026-11-12）。
- 基準: main `1cafe8e2fba50ceec645be06e40b45a1e9aeb039`、[現行製品仕様](spec.md) v2.27。
- この文書は差分検討の正本であり、現行仕様・既存設計の正本を置き換えない。採用が決まった項目だけ、対象の仕様正本・実装計画・テスト設計へ反映する。
- 入り口: [調査DB](references/index.md) → [共通機能モデル](common-capabilities.md) → 本書。
- 今回の範囲: 公開資料とリポジトリの静的確認による改善案。アプリの動作試験、性能計測、実装は行っていない。

## 1. 維持する要件

[spec.md §2・§24・§25](spec.md)と[実装者ガイド](20260928-implementation-guide.md)を優先する。利用者に依存パッケージやビルドを要求しないこと、ブラウザ標準API、既存の入力・録画・表示の固定方針を維持する。新しい参考製品の豊富さを理由に、重いノードエディタや外部エンジンへ全面移行しない。

## 2. 現状と差分を扱う規則

各改善IDに「現状の根拠 → 参考ID → 共通機能ID → 差分 → 受入条件 → 非対象」を付ける。既存コードにあるという静的確認と、動作しているという実機検証を区別する。未実行テストを合格にしない。仕様の旧節と最新節が食い違う場合、古い記述をそのまま実装基準にしない。

## 3. 優先改善案

### IMP-00: 現行仕様の歴史的な記述を整理する

- 現状: spec §20にはPhase 19(WebGL2)未着手の記述が残るが、GPUの別経路と統合は実在する。§21の「背景が常に黒」と§25の「黒または白」も整合確認が必要。
- 差分案: 旧計画と現在のGPU方式を区別し、背景は現行の固定方針を参照する。過去の計画を実装済みへ日付だけで変更しない。
- 受入条件: 対象節ごとに現行／歴史／未実装の区分と根拠を示し、参照先が一致する。矛盾を解消する仕様変更PRを作り、承認前は本案のままとする。
- 非対象: 過去ログの書換え、実行していない試験の合格扱い。


### IMP-01: 能力表を正本化し、使えない機能の理由を一貫して示す

- 現状: [renderer-registry.js](../js/renderer-registry.js)に既にcapabilitiesがあり、2Dの対応操作やGPU種別を宣言している。2D／GPU、ファイル／マイク、通常録画／オフライン書出しで制約が異なる。[spec.md §1.1・§9](spec.md)および[README](../README.md)を参照。GPUはマイク入力不可・事前解析が必要。
- 関連: CAP-01/05/07/09、REF-01/02/03/04。
- 差分案: 既存capabilitiesを置き換えるのではなく、不足する入力・出力軸を補う。各描画タイプと出力モードに対して、対応入力、先読み要否、必要API、無効になる設定、機能低下時の挙動を一覧化する。将来の実装ではUIとAPIが同じ能力定義を参照する。
- 受入条件:
  - 現行2D/GPU全タイプの「入力×出力」組合せに、対応／条件付き／非対応と理由が一つずつ定義される。
  - 非対応組合せは、無反応や黙った設定無視ではなく理由を確認できる。
  - プリセット読込、入力切替、録画開始でも同じ判定となる検証例がある。
- 非対象: GPUライブ対応の実装、全機能を全タイプへ強制適用すること。

### IMP-02: 周波数軸とレイヤー分割を別の仕様として明確にする

- 現状: [Issue #68](https://github.com/masa-san-jp/Audio-visual-analyzer/issues/68)に対数軸の要求がある。Issue本文の「tests/が無い」や旧getLayerData経路は古い。現行の[FramePipeline](../js/frame-pipeline.js)とcomputeLayerRange、既存tests/を基準にする。[bars.js](../js/renderers/bars.js)は線形ビン抽出を行う。現行はメル尺度レイヤー分割も持つため「対数表示＝メル分割」と混同しない。
- 関連: CAP-03/04/05、REF-04/05。
- 差分案: #68を既存の実装課題として再利用。軸の写像、ビン集約、層の帯域境界、端点、無効値の扱いを分離して設計する。対象帯域の数値は現行仕様から参照する。
- 受入条件:
  - #68の周波数端点・等オクターブ間隔・単調性・従来モード回帰の条件を満たす設計になっている。
  - レイヤー境界と画面座標の対応が、線形／対数／既存メル分割の各組合せで定義される。
  - 正弦波、複数トーン、帯域外入力で期待される画面位置と層が示される。
- 非対象: #68の重複起票、対数軸が解決済みとの断定、単位や帯域の無断変更。

### IMP-03: 解析・描画・書出しの再現性を比較可能な契約にする

- 現状: 既にMFSの共有、seed、固定時間を使う経路を持つ。[renderer-contract.md](renderer-contract.md)と既存Phase 15/16/18・GPU設計を正本とする。
- 関連: CAP-02/03/05/07、REF-01/03/05。
- 差分案: 既存の再現性保証を一つの比較マトリクスに整理し、同一性を保証しないフォールバック経路を明示する。ビット一致と許容誤差付き画像一致、特徴量の一致を分ける。
- 受入条件:
  - 入力、設定、seed、FPS、開始時刻、解析経路、ブラウザ、GPU、許容差を検証ケースごとに記録できる。
  - 通常再生／シーク再生／オフライン出力の対応する時刻を比較する手順がある。
  - null特徴、AudioWorklet不可、途中キャンセル後の再実行を別ケースとする。
  - 現行テストがある部分は新設せず、そのテストIDを対応させる。不足分だけ追加計画にする。
- 非対象: 異なるGPUで無条件にビット一致を約束すること、実測なしの性能保証。

### IMP-04: 設定から表示変化までの経路を追跡可能にする

- 現状: 設定、音特徴、色・形状・自動演出・GPU固有制御の経路が複数ある。
- 関連: CAP-04/06/08、REF-01/02/03/04。
- 差分案: 設定ごとに、保存キー、利用する描画タイプ、値域、効果、無効条件、変換規則、正本の節を対応させる。無効時も保存値を保持する既存動作は維持する。
- 受入条件:
  - 現行の公開設定が、適用される機能または非適用理由へ辿れる。
  - 自動演出／GPU選択／旧設定移行時の実効値と保存値の差が説明される。
  - 代表設定の下限・上限・既定値の表示例と、変更しても影響しない組合せの拒否／非表示方針が定義される。
- 非対象: 参考製品のUIをそのまま模倣すること、全パラメーターを常に表示すること。

## 4. 別判断とする拡張

| 候補 | 今回決めない理由 | 着手前に必要な決定 |
|---|---|---|
| 外部シンセの音声入力 | MediaStreamの受け口があっても、アプリ間受渡し・権限・クロック・停止動作は未設計 | 同一ページ／別タブ／別プロセス、接続方法、二重音声出力の防止、対象2D/GPU |
| エージェント操作 | 現行製品の主目的とは別の操作面。通信方式を調査だけで確定しない | 操作範囲、状態照会、認可、再試行、競合、危険操作の境界 |
| GPUのライブ対応 | 全曲先読みと因果的ライブ処理は同じではない | 先読み依存を外した場合の演出・性能・同期・品質の基準 |
| シーンを組むノードUI | 参考製品に存在するが、簡素なUIの現行方針とトレードオフ | 必要な制作体験、最小の操作範囲、既存UIとの共存 |

## 5. 次の作業と完了条件

これは実装指示ではなく、改善を採用する前の設計作業順である。

1. 調査DBの対象・確認範囲をレビューし、採用候補と保留を選ぶ。
2. IMP-00〜04の現状根拠を実装ファイル／既存テストへ対応させ、静的確認だけで不明な点を実機検証項目にする。
3. 採用項目について既存の仕様正本と計画書を更新するPRを作成する。#68の既存受入条件を捨てない。
4. 仕様変更の承認後、機能単位で実装・回帰テスト・観察結果を記録する。

本仕様案の完了は、調査の出典、共通機能、現状との違い、受入条件、保留理由を相互に追跡できること。製品の改善完了は、採用済み仕様に沿った実装と実測の検証が終わった時であり、文書を書いただけでは完了しない。

## 6. 実装着手前に固定する具体契約と残課題

- IMP-01の能力宣言案は `input.file/input.mic/output.preview/output.realtimeRecord/output.offline` をそれぞれ `supported | unsupported | conditional` とし、conditionalには条件と拒否理由を必須とする（**新設案、未実装**）。未知はsupportedにしない。既存renderer capabilitiesを削除・置換せず、現行経路の事実を調べた上で追加する。
- IMP-02は描画位置のみの尺度変更とする案。正の周波数fについて `x/W=log(f/fMin)/log(fMax/fMin)`、fMin=50、fMax=min(15000,sampleRate/2)。fMax≤fMinでは描画しない。これは**提案式**で、現行melレイヤー境界は変更しない。bin集約方式（最大/RMS/平均）と棒数への対応は未確定で、#68の実装計画で固定する必要がある。
- IMP-03の最小比較は同一PCM・設定・解析経路・FPS・サイズ・背景・seed・初期状態で実施する。[共通仕様§5](common-capabilities.md#5-現行2dに適用できる具体契約確認済み基準時点の抜粋)のV-01〜06を値域・更新則の入口とする。現行残像はFPS依存、resetはrenderer固有状態を初期化しないことを前提に比較条件を組む。FPSをまたぐ等価性を現状の合格条件にしない。
- IMP-04は設定本文の破壊的変更ではなく、検証記録にcommit、入力識別、sampleRate、FFT/hop、解析経路、AGC、FPS、サイズ、seed、初期化手順を添付する案。保存形式の新versionは本PRでは決めない。

本PRで完了するのは、出典付き初期DB、現行2Dの具体契約と検証ベクトル、追跡可能な改善差分まで。全CAPの統一API仕様、製品の採否決定、画像・A/V許容差、性能予算の実測、実装・GPU画質試験は未完了である。提案のレビュー後、採用項目の実装計画で残る選択を固定する。
